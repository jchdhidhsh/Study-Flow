# 需求文档

## 一、项目概述

**项目名称**：Study-Flow  
**项目类型**：学习任务管理系统（DDD 领域驱动设计）  
**核心功能**：帮助用户管理学习任务、设置提醒、分类标签

## 二、功能需求

### 2.1 核心功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 创建任务 | 用户可以创建学习任务，设置标题、描述、优先级、截止日期 | P0 |
| 完成任务 | 用户可以标记任务为已完成 | P0 |
| 任务列表 | 按用户筛选任务列表 | P0 |
| 优先级排序 | 按优先级高到低排序任务 | P1 |
| 到期提醒 | 任务到期前1天自动提醒 | P1 |
| 高优先级提醒 | 高优先级任务创建后即时提醒 | P1 |
| 每日汇总 | 当日未完成任务汇总提醒 | P2 |

### 2.2 迭代新增功能（实验四）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 标签分类 | 创建和管理标签 | P0 |
| 标签绑定 | 任务可绑定多个标签 | P0 |
| 标签筛选 | 按标签筛选任务列表 | P1 |

## 三、业务规则

### 3.1 任务规则

- 任务必须关联一个用户
- 任务标题不能为空
- 任务优先级：HIGH / MEDIUM / LOW
- 任务状态：PENDING / IN_PROGRESS / COMPLETED / CANCELLED
- 已取消的任务不可完成
- 已完成的任务重复调用 complete() 幂等

### 3.2 提醒规则

| 策略类型 | 触发条件 | 提醒时机 |
|----------|---------|---------|
| DUE_DATE | 任务有截止日期且状态非完成 | 到期前1天 |
| HIGH_PRIORITY | 任务优先级为 HIGH 且未完成 | 创建后即时 |
| DAILY_SUMMARY | 任务状态非完成 | 当日汇总 |

### 3.3 标签规则

- 标签名称不能为空
- 标签可被多个任务引用（多对多）
- 标签可单独查询和删除

## 四、数据模型

### 4.1 核心实体

```
User
├── id: string
├── name: string
└── createdAt: Date

Task
├── id: string
├── name: string
├── description: string
├── taskListId: string
├── dueDate: Date
├── priority: Priority
├── status: TaskStatus
├── completedAt: Date
├── createdAt: Date
└── updatedAt: Date

Tag
├── id: string
├── name: string
└── createdAt: Date

TaskTag
├── taskId: string
└── tagId: string
```

### 4.2 值对象

```
TaskStatus
├── PENDING: { state, label }
├── IN_PROGRESS: { state, label }
├── COMPLETED: { state, label }
└── CANCELLED: { state, label }

Priority
├── HIGH: { level, label, value }
├── MEDIUM: { level, label, value }
└── LOW: { level, label, value }
```

## 五、非功能性需求

- **可扩展性**：新增提醒策略无需修改现有代码（策略模式）
- **可测试性**：每个策略可独立测试
- **代码质量**：ESLint + Prettier 规范，101 个单元测试用例
- **持续集成**：GitHub Actions 自动构建和测试

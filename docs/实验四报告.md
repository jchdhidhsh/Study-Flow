## 4. 任务 3：配置持续集成

### 4.1 CI 配置文件

**文件位置**：`.github/workflows/ci.yml`

**CI 流程**：
```yaml
1. checkout          - 拉取代码
2. setup-node        - 配置 Node.js 20 环境
3. npm ci            - 安装依赖
4. npm run lint      - 执行静态检查
5. npm test          - 运行单元测试
6. Upload results    - 保存测试结果
```

### 4.2 为什么这些检查是必要的

| 检查 | 必要性 |
|------|-------|
| npm ci | 确保依赖版本一致，避免幽灵依赖 |
| npm run lint | 早期发现代码风格和潜在错误 |
| npm test | 确保每次提交不破坏现有功能 |

### 4.3 CI 能拦截的质量问题

- 语法错误
- 代码风格违规
- 单元测试失败
- 回归问题
- 覆盖率为零

### 4.4 仍需人工评审

- 业务逻辑正确性
- 设计模式选择
- API 契约变更
- 异常处理完整性
- 注释和文档质量

### 5.2 失败点与改进行为

**失败点 1**：策略模式重构后引入的问题

### 5.3 AI 在独立开发中的价值与局限

**价值**：
- 快速识别代码异味和潜在问题
- 发现潜在回归问题
- 提供修复建议和方案比较
- 辅助生成文档和测试代码

**局限**：
- 无法理解业务上下文
- 不能替代人工做最终判断
- 审查结果需人工验证
- 可能产生误报（如风格问题）

# StudyFlow 学习任务管理系统 - 项目结构说明

---

## 1. 分层架构概述

本项目采用 **领域驱动设计（DDD）** 的经典四层架构：

```
interfaces（接口层）
        ↓
application（应用层）
        ↓
  domain（领域层）
        ↑
infrastructure（基础设施层）
```

| 层级 | 职责 | 依赖关系 |
|------|------|----------|
| **interfaces** | 负责与外部系统（用户、第三方服务）交互，展示数据 | 依赖 application |
| **application** | 编排领域逻辑，处理用例，实现业务服务 | 依赖 domain |
| **domain** | 承载核心业务逻辑、领域实体、值对象、业务规则 | 核心，不依赖其他层 |
| **infrastructure** | 实现数据持久化、外部服务调用、技术组件 | 可被其他层依赖 |

## 3. 各层职责详解

### 3.1 domain（领域层）—— 最核心、最稳定

- **model/entity**：领域实体，包含业务逻辑方法（如 `Task.complete()`）
- **model/vo**：值对象，不可变，仅描述属性（如 `Priority.HIGH`）
- **aggregate**：聚合根，封装边界内的实体，保证不变量一致
- **service**：领域服务，当业务逻辑不属于任何单一实体时，放入领域服务
- **repository**：仓储接口，声明数据存取能力（接口定义在领域层，实现在基础设施层）
- **event**：领域事件，记录业务中发生的重要事件

### 3.2 application（应用层）—— 用例编排

- **service**：应用服务，接收命令/查询，调用领域层完成业务流程，不含业务逻辑
- **command**：命令对象，封装写操作的入参
- **query**：查询对象，封装读操作的入参
- **dto**：数据传输对象，在应用层与接口层之间传递数据

### 3.3 infrastructure（基础设施层）—— 技术实现

- **persistence/repository**：实现领域层定义的仓储接口
- **persistence/mapper**：ORM 映射（表与实体的转换）
- **persistence/entity**：数据库表对应的实体类
- **notification**：提醒推送、消息发送等技术组件
- **security**：密码加密、会话管理等安全组件

### 3.4 interfaces（接口层）—— 外部交互入口

- **controller**：接收 HTTP 请求，调用应用服务，返回响应
- **dto/request**：外部请求数据结构的定义（校验注解等）
- **dto/response**：对外暴露的数据结构，统一响应格式

## 4. 依赖方向规则

```
  ┌─────────────────────────┐
  │      interfaces         │  ← 依赖 application
  │    （接口层，入口）       │
  └───────────┬─────────────┘
              │
  ┌───────────▼─────────────┐
  │      application         │  ← 依赖 domain
  │     （应用层，用例）       │
  └───────────┬─────────────┘
              │
  ┌───────────▼─────────────┐
  │        domain           │  ← 核心，不依赖任何层
  │     （领域层，业务）       │
  └───────────────────────────┘

  infrastructure 可被上述各层依赖（通过依赖倒置）
  ┌───────────────────────────┐
  │    infrastructure         │
  │   （基础设施层，技术）     │
  └───────────────────────────┘
```

> **关键原则**：领域层是核心，业务规则和领域模型不应依赖任何外部技术实现。所有技术细节（数据库、通知、安全）都放在基础设施层，通过**依赖倒置原则（DIP）**——领域层定义接口（repository 接口），基础设施层实现这些接口。

## 5. 文件命名规范

| 类型 | 命名规范 | 示例 |
|------|----------|------|
| 实体类 | 领域名 | `Task.java`、`User.java` |
| 值对象 | 领域名 | `Priority.java`、`TaskStatus.java` |
| 聚合根 | 领域名 + Aggregate | `TaskListAggregate.java` |
| 领域服务 | 领域名 + DomainService | `TaskDomainService.java` |
| 应用服务 | 领域名 + ApplicationService | `TaskApplicationService.java` |
| 仓储接口 | 领域名 + Repository | `TaskRepository.java` |
| 仓储实现 | 领域名 + RepositoryImpl | `TaskRepositoryImpl.java` |
| 控制器 | 领域名 + Controller | `TaskController.java` |
| 命令对象 | 动名词 + Command | `CreateTaskCommand.java` |
| 查询对象 | 动名词 + Query | `TaskStatisticsQuery.java` |
| DTO | 领域名 + DTO | `TaskDTO.java` |

# 领域模型设计

## 一、DDD 分层架构

```
src/
├── application/          # 应用层
│   └── service/         # 应用服务（用例编排）
├── domain/              # 领域层
│   ├── model/           # 领域模型
│   │   ├── entity/      # 实体
│   │   └── vo/         # 值对象
│   ├── service/        # 领域服务
│   └── repository/     # 仓储接口

```

## 二、核心实体

### 2.1 User（用户）

```javascript
    super(id);
    this.name = name;
    this.createdAt = new Date();
  }
}
```

**职责**：作为任务的拥有者

### 2.2 Task（任务）

```javascript
class Task extends BaseEntity {
  constructor({ id, name, description, taskListId, dueDate }) {
    super(id);
    this.name = name;
    this.description = description;
    this.taskListId = taskListId;
    this.dueDate = dueDate;
    this.priority = Priority.MEDIUM;
    this.status = TaskStatus.PENDING;
    this.completedAt = null;
  }

  complete() {
    if (this.status.state === 'CANCELLED') {
      throw new Error('已取消的任务不可完成');
    }
    if (this.status.state !== 'COMPLETED') {
      this.status = TaskStatus.COMPLETED;
      this.completedAt = new Date();
      this.updatedAt = new Date();
    }
    return this;
  }
}
```

**职责**：
- 封装任务业务规则
- 管理任务状态流转
- 提供状态模式方法

**业务不变量**：
- ID 不能为空
- 已取消的任务不可完成
- 完成任务自动设置 completedAt

### 4.2 具体策略实现

| 策略类 | 职责 |
|--------|------|
| DueDateReminderStrategy | 到期前1天提醒 |
| HighPriorityReminderStrategy | 高优先级即时提醒 |
| DailySummaryReminderStrategy | 当日汇总提醒 |

### 4.3 ReminderStrategyFactory（策略工厂）

```javascript
class ReminderStrategyFactory {
  constructor() {
    this.strategies = new Map();
  }

  register(type, strategy) {
    this.strategies.set(type, strategy);
  }

  get(type) {
    const strategy = this.strategies.get(type);
    if (!strategy) {
      throw new Error(`Unknown reminder type: ${type}`);
    }
    return strategy;
  }
}
```

**职责**：管理策略注册和获取，支持运行时扩展

## 六、设计模式应用

### 6.1 策略模式（Strategy Pattern）

**应用场景**：提醒规则系统

**好处**：
- 新增提醒策略无需修改 ReminderService
- 每个策略可独立测试
- 策略可复用

### 6.2 工厂模式（Factory Pattern）

**应用场景**：策略创建

**好处**：
- 集中管理策略实例
- 支持运行时注册新策略

### 6.3 状态模式（State Pattern）

**应用场景**：Task.complete()

**好处**：
- 封装状态转换逻辑
- 业务规则内聚
- 便于扩展新状态

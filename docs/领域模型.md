# StudyFlow 学习任务管理系统 - 领域模型

---

## 1. 实体与值对象总览

| 类别 | 名称 | 说明 |
|------|------|------|
| **实体** | User | 具有唯一标识（id）的用户主体，生命期内可被修改 |
| **实体** | Task | 具有唯一标识（id）的任务主体，状态可流转，生命周期内可被更新和删除 |
| **实体** | TaskList | 具有唯一标识（id）的任务清单，可包含多个任务，支持增删改 |
| **实体** | ReminderPolicy | 具有唯一标识（id）的提醒策略，与具体任务绑定 |
| **实体** | ProgressReport | 具有唯一标识（id）的进度报表，反映用户在某一时刻的统计数据 |
| **值对象** | Priority | 优先级枚举（高/中/低），无唯一标识，仅描述属性 |
| **值对象** | TaskStatus | 任务状态枚举（待办/进行中/已完成/已取消），无唯一标识 |
| **值对象** | ReminderTime | 提醒时间点，无唯一标识，描述时间信息 |
| **值对象** | TaskStatistics | 统计数据值对象（总任务数、完成数、完成率等），无唯一标识 |

---

## 2. 核心实体详细定义

### 实体 1：User（用户）

```
User（用户）
├── id: Long              // 唯一标识，主键
├── username: String       // 用户名，唯一，不可为空
├── passwordHash: String   // 密码哈希值（加密存储）
├── createdAt: DateTime    // 账户创建时间
└── updatedAt: DateTime    // 信息更新时间
```

**实体判断依据**：用户具有全局唯一 id，不同用户的 username 必须互不重复，系统需要跟踪用户的创建和更新时间。

---

### 实体 2：Task（学习任务）

```
Task（学习任务）
├── id: Long                // 唯一标识，主键
├── name: String            // 任务名称，必填，不可为空
├── description: String      // 任务描述，选填
├── taskListId: Long         // 所属任务清单ID，外键引用TaskList
├── priority: Priority       // 优先级（高/中/低），默认中等
├── status: TaskStatus       // 任务状态（待办/进行中/已完成/已取消），默认待办
├── dueDate: DateTime        // 截止时间，必填，不可为空
├── reminderPolicy: ReminderPolicy  // 关联的提醒策略（聚合根内部引用）
├── createdAt: DateTime      // 创建时间
├── updatedAt: DateTime      // 更新时间
└── completedAt: DateTime    // 完成时间（当状态变为已完成时记录）
```

**实体判断依据**：Task 是系统的核心领域对象，每个 Task 具有全局唯一 id，其状态 priority、status 等属性在生命期内会发生变化，Task 可被独立删除而不影响 User 的存在。

---

### 实体 3：TaskList（任务清单）

```
TaskList（任务清单）
├── id: Long                // 唯一标识，主键
├── name: String            // 清单名称，必填，不可为空
├── userId: Long            // 所属用户ID，外键引用User
├── description: String     // 清单描述，选填
├── createdAt: DateTime     // 创建时间
└── updatedAt: DateTime     // 更新时间
```

**实体判断依据**：TaskList 具有唯一 id，用户可创建多个清单，清单内的任务数量会变化，清单本身可被删除重命名。

---

### 实体 4：ReminderPolicy（提醒策略）

```
ReminderPolicy（提醒策略）
├── id: Long                // 唯一标识，主键
├── taskId: Long            // 关联任务ID，外键引用Task
├── reminderTime: DateTime  // 提醒触发时间点
├── isEnabled: Boolean      // 提醒是否开启，默认开启
├── createdAt: DateTime    // 创建时间
└── updatedAt: DateTime    // 更新时间
```

**实体判断依据**：ReminderPolicy 具有唯一 id，其 reminderTime 和 isEnabled 在生命周期内可被修改，是 Task 的一个可独立管理的策略子实体。

---

### 实体 5：ProgressReport（学习进度报表）

```
ProgressReport（学习进度报表）
├── id: Long                // 唯一标识，主键
├── userId: Long            // 所属用户ID，外键引用User
├── reportDate: Date        // 报表统计日期
├── totalTasks: Integer     // 总任务数
├── completedTasks: Integer // 已完成任务数
├── inProgressTasks: Integer // 进行中任务数
├── pendingTasks: Integer   // 待办任务数
├── cancelledTasks: Integer // 已取消任务数
├── completionRate: Double   // 完成率（百分比）
├── priorityStats: Map<Priority, Integer> // 优先级分布统计
└── generatedAt: DateTime    // 报表生成时间
```

**实体判断依据**：ProgressReport 具有唯一 id，每条报表记录反映用户在特定日期的统计快照，数据随时间推移会产生新的报表记录。

---

## 3. 值对象详细定义

### 值对象 1：Priority（优先级）

```
Priority（优先级）
├── level: Enum             // 枚举值：HIGH(高), MEDIUM(中), LOW(低)
```

**值对象判断依据**：Priority 描述的是任务的紧急程度分类，无唯一标识，两个 Priority 对象即使 level 相同也视为相等，不可单独存在，只能依附于 Task 而存在。

---

### 值对象 2：TaskStatus（任务状态）

```
TaskStatus（任务状态）
├── state: Enum             // 枚举值：PENDING(待办), IN_PROGRESS(进行中),
                             //           COMPLETED(已完成), CANCELLED(已取消)
```

**值对象判断依据**：TaskStatus 描述任务的当前阶段，无唯一标识，不可独立存在，只作为 Task 的属性组成部分。

---

### 值对象 3：ReminderTime（提醒时间）

```
ReminderTime（提醒时间）
├── time: DateTime          // 提醒触发时间点
└── offsetMinutes: Integer  // 相对于截止时间的偏移分钟数
```

**值对象判断依据**：ReminderTime 仅描述一个时间语义，无唯一标识，可被重新设置而无需对象唯一性追踪。

---

### 值对象 4：TaskStatistics（任务统计）

```
TaskStatistics（任务统计）
├── totalCount: Integer      // 总任务数
├── completedCount: Integer  // 已完成任务数
├── inProgressCount: Integer // 进行中任务数
├── pendingCount: Integer   // 待办任务数
├── completionRate: Double   // 完成率（百分比）
└── highPriorityCount: Integer  // 高优先级任务数
```

**值对象判断依据**：TaskStatistics 是从多个 Task 聚合计算出的统计数据，无唯一标识，不存在独立的生命周期，仅在展示层作为统计结果使用。

---

## 4. 实体关联关系

```
User（用户）
│  1
 │◆───────────◆ N
 │            │
 │            │ 1
 │            │◇───────────◇ N
 │            │            │         TaskList
 │            │            │
 │            │ 1          │
 │            │◇───────────◇ N
 │                         │           Task
 │                         │
 │                         │ 1..1
 │                         │◇──────────◇ 1
 │                                      │   ReminderPolicy
 │                                      │
 │         Priority（值对象）◇──────────┤
 │         TaskStatus（值对象）◇────────┤
 │         TaskStatistics（值对象）     │
 │                                      │
 │         ProgressReport（实体）◇─────┤
 │              │
 │              │ N
 │              │◇───────────────────◇ 1
 │                                     │
 │         ReminderTime（值对象）◇────┘
```

| 关联关系 | 说明 | 关系类型 |
|----------|------|----------|
| User → TaskList | 一个用户可拥有多个任务清单 | 1 : N |
| User → Task | 一个用户可拥有多个学习任务（通过TaskList间接关联） | 1 : N（经由TaskList） |
| User → ProgressReport | 一个用户可生成多条进度报表记录 | 1 : N |
| TaskList → Task | 一个清单可包含多个任务 | 1 : N |
| Task → ReminderPolicy | 一个任务可绑定一个提醒策略（可选） | 1 : 1 |
| Task → Priority | 任务具有一个优先级属性 | 依赖（值对象） |
| Task → TaskStatus | 任务具有一个状态属性 | 依赖（值对象） |
| ProgressReport → TaskStatistics | 报表中包含统计值对象 | 包含（值对象） |
| ReminderPolicy → ReminderTime | 提醒策略中包含提醒时间值对象 | 包含（值对象） |

---

## 5. 聚合根划分

| 聚合根 | 包含的实体 | 包含的值对象 |
|--------|-----------|-------------|
| **User** | User（自身） | — |
| **TaskList** | TaskList、Task、ReminderPolicy | Priority、TaskStatus、ReminderTime |
| **ProgressReport** | ProgressReport | TaskStatistics |

**说明**：
- **User 聚合**：用户作为账户层面的聚合根，管理自身信息。
- **TaskList 聚合**（核心业务聚合）：TaskList 是任务清单聚合的聚合根，内部包含 Task，Task 内部包含 ReminderPolicy。Priority、TaskStatus、ReminderTime 作为值对象嵌入在 Task 或 ReminderPolicy 中。
- **ProgressReport 聚合**：ProgressReport 作为报表聚合根，包含 TaskStatistics 值对象。

---

## 6. 实体 vs 值对象区分

| 判断维度 | 实体 | 值对象 |
|----------|------|--------|
| **唯一标识** | ✅ 拥有全局唯一 id | ❌ 无唯一标识 |
| **生命周期** | 独立创建、更新、删除 | 不可独立存在，随实体创建/销毁 |
| **相等性判断** | 按 id 判断是否同一对象 | 按属性值判断是否相等 |
| **示例** | User, Task, TaskList, ReminderPolicy, ProgressReport | Priority, TaskStatus, ReminderTime, TaskStatistics |

## 7. 领域不变量（业务约束规则）

| 不变量ID | 不变量名称 | 约束规则描述 | 影响范围 |
|----------|-----------|-------------|----------|
| **INV-01** | 清单下任务归属约束 | 任务必须从属于一个 TaskList，不可存在游离（无归属清单）的任务。删除清单时需处理其下的任务（如一并删除或提示用户）。 | Task、TaskList |
| **INV-02** | 任务状态流转约束 | 任务状态只能按以下顺序流转：待办 → 进行中 → 已完成；或任意非完成状态可流转为已取消。已完成和已取消状态不可再变更回待办或进行中。 | Task |
| **INV-03** | 提醒时间有效性约束 | 提醒触发时间必须早于或等于任务的截止时间（dueDate），否则提醒策略无效。提醒开启时（isEnabled=true）必须同时满足提醒时间有效。 | ReminderPolicy |
| **INV-04** | 用户数据隔离约束 | 用户只能访问和操作自己创建的 TaskList、Task、ReminderPolicy、ProgressReport 数据，任何跨用户的数据访问请求必须被系统拒绝。 | 所有实体 |
| **INV-05** | 任务名称非空约束 | 任务名称（name）和清单名称（name）不能为空字符串或仅包含空白字符，长度需在合理范围内（如 1~100 字符）。 | Task、TaskList |
| **INV-06** | 截止时间合理性约束 | 任务的截止时间（dueDate）必须大于当前时间（创建时），确保任务有明确的有效期。 | Task |
